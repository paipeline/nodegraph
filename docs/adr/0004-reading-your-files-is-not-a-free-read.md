# 去读用户文件的 GET 不算「读」

ADR-0003 决定读操作(GET/HEAD)不上锁,理由是同源策略挡得住跨站读响应体,而上锁只会把用户锁在自己的页面外面。那条决定继续有效,这里只把「读」这个词切成两半:**报告 nodegraph 自己知道的事**的读继续不要 key(`/api/graph`、`/api/nodes`、页面本身),**跑去读用户仓库里的文件**的读要 key(今天是 `/api/diffs`,规则写在 `core/guard` 的 `READS_YOUR_FILES` 里)。

分界线是这个:同源策略保护的是**答案**,不是产生答案的**动作**。`<script src>` 和 `<img src>` 根本不发 Origin,浏览器里任何一个页面都能让 handler 跑起来——它读不到响应体,但它不需要读:handler 已经跑了。对一条只把已经记在 `graph.json` 里的东西念一遍的路由,这个代价是划算的;对一条要遍历工作区、把 git 从没听说过的文件按内容读进来(每个 Node 最多 4MB)、并为此在每个 Workspace 里起一个 git 的路由,不划算。而这条路由页面每两秒轮询一次,所以它同时也是一个放大器:一个外站页面每秒打一千次,nodegraph 就每秒起两千个 git 进程去啃用户的硬盘。

「用户的源码能不能从一个不需要认证的本地端口读出去」——答案是不能。这不是因为跨站页面能读到数字(它读不到),而是因为**决定要不要去读的人,必须是拿着本次运行 key 的那张页面**。

## Considered Options

- **维持原状,`/api/diffs` 继续不要 key**:被否。这正是上一轮留下来没答的问题。理由曾经是「危险的是它其实不是个读操作,而那部分已经修好了」;修好之后它仍然会为一次匿名请求去遍历工作区、读文件内容、起 git 进程。同源策略保护不了这些动作。
- **只靠 Origin 检查**:被否。理由和 ADR-0003 拒绝「只查 Origin」时完全一样,而且在这里更尖锐:标签驱动的请求(`<script src>` / `<img src>`)压根不发 Origin,门卫看不见工牌就放行等于没有门卫。
- **把所有 GET 都上锁,包括 `/api/graph` 和 `/api/nodes`**:被否。页面要先能画出来,而且这两条只是把 nodegraph 自己的记事本念一遍;把它们锁上会让 ADR-0003 明确保留的「`vite dev` 的 proxy 还能用来看图」彻底失效,换来的只是把已经在 `graph.json` 里的东西藏起来。
- **按路径前缀判断(`/api/` 全锁、`/api/read-` 全开之类)**:被否。那会变成一条关于拼写的规则,下一个加进受保护前缀的路由会继承一把没人决定给它的锁,反过来也一样。规则按整条路径列举,加一条就得写一行,写那一行的时候人必须想一下。
- **给 `/api/diffs` 限流而不是上锁**:被否。限流只让放大器变慢,不改变「任何页面都能命令 nodegraph 去读用户的文件」这件事,而这件事本身就是不该有的。

## Consequences

- 页面轮询 diff 时要带 `x-nodegraph-key`(`web/src/App.tsx`)。图和 diff 是两次 fetch,只有后一次带 key。
- `vite dev` 的 proxy 从此看得到图、看不到每个 Node 的增删行数——ADR-0003 说过那个 proxy「只能用来看图」,这里正好落在那句话里面。要看完整的东西就 `pnpm build:web`。
- 判断挪进了 `core/guard` 的 `admit`,靠 `Attempt.path`(query string 已剥掉,由 `server/gate` 从 wire 上取)。它是纯函数,所以「哪条路由要 key」是拿普通数据测的,不是靠起一个服务器测的。
- 这类洞和 ADR-0003 说的一样是回归性的:**每加一条会去读用户仓库内容的 GET,都要同时把它加进 `READS_YOUR_FILES`,并加一条「没有 key 就是 403」的测试**,否则下一条路由又是敞开的。
