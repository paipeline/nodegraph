# Fork 捕获的是一个瞬间,而不是一个 commit

一次 Fork 复制的是父 Node **此刻**的完整状态——包括还没提交的改动——并且只允许在 agent 已经停下来等待时发起。选这个是因为用户心里的"从这里分出去"指的就是他此刻在屏幕上看见的那个状态;若改成从最近一次 commit 切,用户每次都得先为了 Fork 而 commit 一次,这个动作就从"存档"退化成"提交流程",产品的手感当场消失。

## Considered Options

- **从父 Node 最近一次 commit 切**:被否。实现干净得多(纯 `git worktree add`,无需搬运脏文件),但强迫用户为了分叉而提交,并且会悄悄丢掉他正在看的那些改动——这是最难被原谅的一类 bug。
- **允许在 agent 跑到一半时 Fork**:被否。Context 会被复制在一个思考进行到一半的状态上,子节点继承到的是一段精神分裂的记忆;同时工作区是移动靶,脏文件的搬运没有一致的时点。附带好处是:限制在回合边界上,天然把节点数量压在人看得懂的范围内。

## Consequences

- WorkspaceProvisioner 必须处理未提交改动的搬运(含新增、删除、重命名),这是它最容易出隐蔽 bug 的地方,必须有测试覆盖。
- UI 上 Fork 按钮在 agent 运行期间必须是禁用的,并说明原因,否则用户会以为坏了。
- Fork 时记录的分叉点 commit SHA 与"此刻的脏状态"是两回事:前者供 DiffService 做稳定基准,后者只影响子节点的初始工作区。
