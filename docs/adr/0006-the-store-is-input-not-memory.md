# 存档文件是输入,不是记忆:一道门,不是六道检查

`.nodegraph/graph.json` 落在用户仓库里,任何东西都能改它——手改、merge 没解干净、别人 clone 来的仓库里本来就带着一个,而它在第一次轮询、任何 Fork 存在之前就被读了。所以从它里面出来的东西**不是 nodegraph 写进去的东西**,而是此刻那块磁盘上的东西。它是一条信任边界,而边界只能有一个关口:`src/core/store.ts`。

规则一句话:**进出这个文件的每一个值都要过 `src/core/store.ts`——nodegraph 写的由它造,nodegraph 读的由它重算并比对;凡不是 nodegraph 自己会写出来的记录,整条不信。**

「整条不信」而不是「把坏字段修好」:修好等于凭空造出一个 nodegraph 从没做过的 Node。不信也不等于可以删——不被相信的记录原样留在磁盘上。

这条 ADR 是被同一个根因逼出来的。四张票、五个 blocker,三个不同的 agent 各自在自己的调用点补了一次:

- `forkPointSha` 进了 git 的 argv,`--output=…` 让「只读」的 `/api/diffs` 截断了任意文件;
- `workspacePath` 成了 git 的工作目录,于是那个目录自己 `.git/config` 里的 `core.fsmonitor` 被每两秒一次的轮询执行;
- `intent` 进了 claude 的 argv,一个写着 `intent: "--dangerously-skip-permissions"` 的 graph.json 点一下就起一个关掉全部权限检查的真 agent;
- 分支名进了 `git worktree add -b`,git 把它当 `git branch` 的参数再解析一遍,一个叫 `-m` 的分支把仓库的 main 改了名(实测重现);
- 一个解析不了的 graph.json 被当成「没有 Fork」读,然后被下一次 Fork 覆写,每个 Node 的血缘永久消失,而 Workspace 还留在磁盘上。

每一次修的都是「这个字段这一次」。第六个调用点仍然是敞开的。所以这一轮不是加第六道检查,是把关口做实。

## Considered Options

- **在每个调用点校验**:被否。这正是被否掉的现状——它已经失败了五次,而且失败得很安静:每一次的修复看上去都是对的,直到下一个字段从下一个出口出去。检查散在调用点上,就没有任何一个地方能回答「还有哪些出口」。
- **把坏字段修好后继续用**(比如把 `--dangerously-skip-permissions` 洗成空):被否。那等于替用户说他没说过的话,也等于把一条 nodegraph 没写过的记录洗成看起来像它写过的。信与不信必须是同一条规则的两面:`forkRecord` 造出来的,`asFork` 就认;造不出来的,就不认。
- **只做「看着无害吗」的黑名单**(挡掉前导 `-`、挡掉 `..`):被否。黑名单永远落后于解释器——git、claude、文件系统各有各的读法,今天挡住 `-` 明天挡不住 `--foo=bar` 里的等号或者别的什么。问「这是不是 nodegraph 自己会写出来的那个字符串」是一个可判定的问题;问「这个字符串危险吗」不是。
- **解析不了就抛异常,整张图挂掉**:被否。每条路由都返回一个 parser error、图上一个 Node 都没有,对一个只负责记「谁从谁分出来」的文件来说反应过度;而且用户看不见发生了什么。
- **解析不了就当空的,继续跑**:被否,而且这是五个 blocker 里最贵的一个。空的会被写,写就是覆盖,覆盖掉的是 git 永远给不回来的东西。
- **写之前先备份一份 graph.json**:被否。备份是另一个要维护、要轮转、要在两个 nodegraph 之间协调的东西,而它解决的问题用「不写」就能解决——不写是免费的、原子的,而且用户手上那个文件就是他要修的那个文件。

## Consequences

- `forkRecord` 和 `sessionRecord` 是造记录的**唯一**入口,并且会**抛**——nodegraph 宁可不写,也不写一条自己读不回来的记录。一次没写下来的 Fork 调用方已经知道怎么回滚;一条写下来了却没人认的记录,是一块磁盘上永远没有 Node 指向它的 Workspace。
- 记录里凡是能由 Node 的名字算出来的字段(`branch`、`workspacePath`),读回来时重算并比对;算不出来的字段(`forkPointSha`、`sessionId`、`intent`)必须长成 nodegraph 写的那个形状——一个 commit、一个 uuid、一条 `readIntent` 原样还回来的话。`sessionId` 要同时过两种解释器:它是 claude argv 里 `--resume` 的值,也是 claude home 下的**文件名**,uuid 两边都安全。
- 读不了的存档:拒绝写、在**每一个** Node 的卡片上说出来(复用 on-fork hook 拒绝那条已经被证明能到达用户眼睛的路径)、文件一个字节不动。修好 json,所有 Node 原样回来。
- 代价是记得住的:形状规则收紧一次,老存档里的记录就可能不再被相信。因为不被相信的记录不会被删,这总是可恢复的;但每一次收紧都必须问一遍「这会让谁的图变空」,并且答案要写进测试。
- 这类洞是回归性的:**每加一个会走进进程的值——argv、工作目录、环境变量、或者一个会被工具解释的路径——都必须同时说清它是从哪道门出来的。**说不清就是 bug。
