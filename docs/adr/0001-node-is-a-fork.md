# 节点是一次 fork,不是一个任务

图上的一个 Node 代表**一次存档**:一份从父节点完整继承下来的 agent 上下文,加一块独占的代码工作区。边表示上下文的继承关系,不表示先后顺序、依赖或工单拆解。选这个是因为在 agent 编程里最贵的资产是 agent 已经建立的理解,而今天唯一能保住它的办法就是不敢尝试第二种做法;把节点定义成 fork,产品才有一个别人抄不走的观点。

## Considered Options

- **节点 = worktree / 开发线**:被否。worktree 只是 fork 的一半(代码那一半),把它当主键会让"继承上下文"这件事无处安放。
- **节点 = PR**:被否。PR 在开发中后期才出生,拿它当主键前半程图上是空的。
- **节点 = agent 自动分解出的子任务**:被否。实测(88 个 repo、189 条分支)显示 git 血缘无法可靠还原"谁从谁分出来",事后考古考不出意图。
- **产品定位成「回收器」**(把忘掉的 blocked agent 和僵尸分支捡回来):被否。痛点真实(在一台真实开发机上实测,有 12 个 blocked agent 无人处理,最久的等了 58 天),但那是一个用列表就能解决的问题,图在其中是花架子。

## Consequences

- Fork 的语义(继承什么、从哪个时间点切、环境算不算)就是这个产品的物理学,必须逐条定死。
- Discard 必须做到干净且可信,否则用户不敢丢,不敢丢就不敢试,产品的全部价值归零。
- 任何不服务于"敢于尝试第二种做法"的功能,v1 不做。
